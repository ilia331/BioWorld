# database/ — базата данни на BioWorld (стъпка 4)

Моделът е описан в [docs/ER_DIAGRAM.md](../docs/ER_DIAGRAM.md).

| Файл | Какво съдържа |
| --- | --- |
| [schema.sql](schema.sql) | 6 таблици, ключове, ограничения (`CHECK`), автоматичен профил при регистрация и RLS правила |
| [seed.sql](seed.sql) | Тестови данни: 3 вида и 5 мисии |
| [rls_test.sql](rls_test.sql) | Проверка с два акаунта, че никой не вижда и не променя чужди игри |

## Как се пуска в Supabase

1. **SQL Editor → New query →** постави цялото съдържание на `schema.sql` → **Run**. Пуска се само веднъж, върху празна база.
2. Същото с `seed.sql`. Накрая трябва да пише 3 вида и 5 мисии.
3. **Authentication → Users → Add user → Create new user:** създай двама тестови потребители (напр. `test-a@bioworld.test` и `test-b@bioworld.test`, с отметка **Auto Confirm User**).
4. Пусни `rls_test.sql`. Всичките 14 реда трябва да са ✅. Тестът изтрива данните, които е създал.

## Какво пазят RLS правилата

| Таблица | Посетител без вход | Влязъл ученик |
| --- | --- | --- |
| species, ecosystems | чете | чете |
| profiles | — | чете и променя само своя профил |
| simulations | — | чете, създава, променя и изтрива само своите игри |
| populations | — | чете, добавя и променя само в своите игри |
| simulation_history | — | чете и добавя само в своите игри; изигран ход **не се поправя** |

## Как е проверено

- Трите файла са изпълнени в локална PostgreSQL база (PGlite), която имитира частите на Supabase: `auth.users`, `auth.uid()` и ролите `anon`/`authenticated`. И 14-те проверки в `rls_test.sql` дават ✅.
- **Контролна проверка:** правилото „Игри: чета своите“ беше нарочно заменено с „всеки вижда всичко“. Тогава тестът показа ❌ на ред 4, т.е. тестът наистина хваща грешка в правата.
- `seed.sql` е пуснат два пъти без грешки и без дублирани редове.
- Ограниченията отказват: отрицателен `max_count`, мисия 6, начална вода над максимума, непознато действие.
- **Първо пускане в Supabase:** редове 3 и 14 излязоха ❌. Причината: Supabase дава всички права на нова таблица по подразбиране, а тестът очакваше грешка за права. Данните всъщност бяха защитени, защото RLS не позволи да се види или промени нито един ред. Поправка: `schema.sql` вече първо отнема правата (`revoke`) и после дава само нужните, а тестът проверява колко реда са видени или променени, а не само дали има грешка. Поправката е проверена локално с правата по подразбиране на Supabase.
